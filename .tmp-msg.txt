feat(db): hybrid MongoDB + Supabase data access layer

MongoDB stays the PRIMARY store for merchants, products, orders and
subscription plans; Supabase is the SECONDARY source (auth users, real-time
tables) that is both merged in and used as a fallback when Mongo is empty,
unconfigured or timing out.

- New lib/hybridDb.ts: never-throwing providers, per-provider diagnostics, and a
  mergeRows() that keeps Mongo values per field while backfilling gaps from
  Supabase. A Supabase-ONLY merchant/plan is still returned, so the fallback
  genuinely adds coverage instead of just substituting one source for another.

  merchantIdentity() deliberately keys on store_slug/store_code FIRST and treats
  Mongo's _id as a document id, never a business key. Keying on `id` first (the
  obvious choice) produced DUPLICATE rows - one per provider - for the same
  store, because Mongo keys off slug and the Supabase mirror keys off the UUID.

- /api/admin/subscription-plans (new): Vercel function, Express mirrors in both
  server.ts files, App Router route, and vercel.json rewrites. Returns the plan
  catalogue merged from Mongo `subscription_plans` / `plans` and the Supabase
  equivalents, with per-plan subscriber counts merged from both subscription
  sources.

- /api/analytics-summary: platform metrics still come from the Mongo aggregation,
  but when the merchant counts come back empty the Supabase
  merchants/subscriptions/domains tables backfill them. Money metrics are never
  invented from Supabase - only counts it can prove. The payload now reports
  `sources` and `supabaseFallback` so a partial result is explainable.

- Error handling: every provider call is wrapped. Missing keys or timeouts on
  EITHER provider return a shaped 200 envelope with per-provider diagnostics,
  never a 404 or 500.

Verified locally: with both databases unconfigured,
GET /api/admin/subscription-plans -> 200 JSON with diagnostics explaining why it
is empty, and POST /api/analytics-summary -> 200 with a formatted fallback
summary plus `reason`/`dbError`. A stubbed two-provider harness confirmed the
merge semantics (Mongo name wins, Supabase phone backfilled, Supabase-only rows
present, both-down degrades cleanly).
