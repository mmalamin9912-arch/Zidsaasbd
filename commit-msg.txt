fix(admin): restore broken nav markup around the Courier tabs in Super Admin

WHAT WAS WRONG
  In src/components/SuperAdminPortalView.tsx the two courier tab panels
  ("Courier Dispatch" and "Courier Orders List") had been pasted INTO the
  Marketplace dropdown menu, between `)}` and the closing `</button>` of each
  sub-menu item:

      {!!sub.badge && sub.badge > 0 && (
        <span ...>{sub.badge}
  )}                                   <-- badge span never closed
                                         <-- the item's </button> vanished
        {activeSubTab === 'courier_dispatch' && (<div>...</div>)}
        {activeSubTab === 'courier_orders' && (<CourierOrdersList ... />)}
                            </button>  <-- stray, now closing the item
      ...

  Because that markup still *parsed*, TypeScript reported nothing. The damage
  only showed at runtime:

    * the whole courier UI was rendered inside the 64-unit-wide dropdown panel,
      so opening either courier tab painted a full dashboard inside a 256px
      popover - the "oversized / zoomed / broken" look;
    * that popover is `absolute` inside the nav row, so its overflow pushed the
      body wider than the viewport and left the page horizontally scrolled
      (which is why everything afterwards seemed to stay broken);
    * the nav item's own </button> was consumed by the splice, so the remaining
      sub-menu buttons got swallowed into the wrong nesting and clicking other
      menus did not switch tabs cleanly.

FIX
  * close the badge span properly and give each nav item back its </button>,
    `);` `})}` and the dropdown card's closing tags, so the tab strip closes
    where it should (`})()}`);
  * move the Courier Dispatch and Courier Orders List panels back to the
    sibling level of every other tab panel - directly inside the admin body
    container, right before the analytics tab;
  * escape the raw `&` in "System & Gateways" as `&amp;` (a bare `&` inside JSX
    text is invalid HTML and was part of the same hand-splice).

VERIFIED (headless Chromium, /admin, real clicks)
  * every state: body scrollWidth === clientWidth (no horizontal overflow)
  * the admin body has exactly 2 children (tab strip + one panel) in every tab
  * Marketplace -> Courier Dispatch -> Courier Orders List -> Platform Settings
    -> back to Dispatch -> Analytics: each opens cleanly at full width, the
    dropdown stays aligned to its trigger, and the active item is highlighted
  * 0 page errors, 0 console errors
  * `npm run lint` and `npm run build` both pass
